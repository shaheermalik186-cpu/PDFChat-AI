# PDFChat-AI
# 📄 Chat with PDF

Upload a PDF and ask questions about it. Answers are generated by **Google Gemini (Flash)**, based **only on your document**, and every answer shows the **source pages** it came from.

Built with [Streamlit](https://streamlit.io), [pypdf](https://pypdf.readthedocs.io) and the [Google Gen AI SDK](https://ai.google.dev/gemini-api/docs/quickstart) (`google-genai`).

## Features

- PDF upload with text extraction (page by page)
- Question answering grounded in the document, with an explicit "not in the document" answer when the PDF doesn't say
- **Source page references**: citations like `[Page 3]` in the answer, plus an expandable preview of those pages
- Chat history with follow-up questions (the last few exchanges are sent to the model)
- Works for small *and* large PDFs (see "How it works")
- Friendly error messages: bad/missing API key, rate limits, wrong model name, corrupted PDF, password-protected PDF, scanned/image-only PDF, oversized file, blocked or empty model response
- Your API key can be typed into the sidebar, or supplied through secrets / environment variables

## How it works

```
PDF upload ──► pypdf extracts text per page ──► clean + (for big files) split into chunks
                                                          │
 question ──► small PDF: send every page ─────────────────┤
              large PDF: rank chunks by keyword relevance │ pick the top matches
                                                          ▼
                     Gemini gets: system rules + recent chat + page-tagged excerpts + question
                                                          ▼
                     answer with [Page N] citations ──► shown with source-page previews
```

- **Small PDFs** (up to about 120,000 characters, roughly 30 to 40 pages of normal text) are sent to Gemini in full. This gives the best answers.
- **Large PDFs** are split into overlapping chunks. For each question the app ranks chunks with a simple TF-IDF-style keyword score (no extra services or packages) and sends the top 10.
- The prompt tells Gemini to use only the excerpts, to say so when the answer isn't there, to cite pages, and to ignore any instructions hidden inside the document.
- Page numbers are the **physical page position** in the file (1 = first page), which can differ from page numbers printed on the pages.

## 1. Get a Gemini API key

1. Open **Google AI Studio's key page**: <https://aistudio.google.com/apikey> and sign in with a Google account.
2. Accept the terms if asked, then click **Create API key** (choose or create a project when prompted).
3. Copy the key and keep it private. Treat it like a password and never commit it to GitHub.
4. If the **Create API key** button is disabled, your Google account/organization may lack permission. Use a personal Google account or ask your administrator.

Google has offered a free tier for some Flash models, but limits change. Check the current limits and prices at <https://ai.google.dev/gemini-api/docs/pricing>.

## 2. Run it locally

You need **Python 3.9 or newer** (3.12 recommended).

```bash
# 1. Go into the project folder (the one containing app.py)
cd chat-with-pdf

# 2. Create and activate a virtual environment
python -m venv .venv
source .venv/bin/activate          # macOS / Linux
# .venv\Scripts\Activate.ps1       # Windows PowerShell

# 3. Install the dependencies
pip install -r requirements.txt

# 4. Start the app
streamlit run app.py
```

Streamlit opens <http://localhost:8501>. Then:

1. Paste your Gemini API key in the sidebar (or set it as described below).
2. Upload a PDF.
3. Ask a question in the chat box at the bottom.

**Optional: avoid pasting the key every time.** Use either option:

- Environment variable, set in the same terminal before `streamlit run app.py`:
  - macOS / Linux: `export GEMINI_API_KEY="your-key"`
  - Windows PowerShell: `$env:GEMINI_API_KEY="your-key"`
- A file named `.streamlit/secrets.toml` inside the project folder containing:
  ```toml
  GEMINI_API_KEY = "your-key"
  ```
  **Never upload this file to GitHub.**

## 3. Upload the project to GitHub (using the website)

1. Sign in at <https://github.com> and click the **+** icon (top right) → **New repository**.
2. Repository name: `chat-with-pdf`. Choose **Public** (needed for the free Streamlit Community Cloud plan with public repos). Leave **"Add a README file" unchecked** because you already have one. Click **Create repository**.
3. On the empty repository page, click the **uploading an existing file** link.
4. Drag and drop the three files: `app.py`, `README.md`, `requirements.txt`. They must sit at the **top level** of the repository, not inside a folder.
5. Write a commit message such as `Add Chat with PDF app` and click **Commit changes**.
6. Refresh the page and confirm all three files are listed.

> Do **not** upload `.streamlit/secrets.toml` or any file containing your API key.

## 4. Deploy on Streamlit Community Cloud

1. Go to <https://share.streamlit.io> and sign in with GitHub (authorize access to your repositories if asked).
2. Click **Create app** (top right). When asked "Do you already have an app?", choose **Yup, I have an app**.
3. Fill in:
   - **Repository**: `your-username/chat-with-pdf`
   - **Branch**: `main`
   - **Main file path**: `app.py`
   - **App URL** (optional): pick a custom `*.streamlit.app` subdomain
4. Click **Advanced settings**:
   - **Python version**: the default (3.12) works well.
   - **Secrets**: see the note below.
   Then **Save**.
5. Start the deployment with the dialog's **Deploy** button. The first build takes a few minutes while it installs `requirements.txt`. You will get a public URL to put in your portfolio.

Button labels on Streamlit Community Cloud change occasionally. If something looks different, follow the on-screen wording and the [official deployment guide](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy).

**Choosing how the API key is handled on a public app**

- **Option A (recommended for a public portfolio demo): leave Secrets empty.** Each visitor pastes their own Gemini key in the sidebar, so nobody can spend your quota.
- **Option B: paste your key in the Secrets box** in TOML format:
  ```toml
  GEMINI_API_KEY = "your-key"
  ```
  Then anyone who opens a public app uses *your* quota. Only do this if the app is private (restricted viewers), or you accept the usage and have set up billing alerts and key restrictions in Google AI Studio / Google Cloud.

You can edit secrets later from the app's settings in your Streamlit workspace. To update the app, edit or re-upload files on GitHub; Streamlit redeploys automatically.

## Configuration

Settings live at the top of `app.py`:

| Setting | Default | Meaning |
|---|---|---|
| `DEFAULT_MODEL` | `gemini-flash-latest` | Model used. `gemini-flash-latest` is an alias to Google's current Flash model. |
| `MAX_PDF_MB` | 25 | Largest accepted upload |
| `MAX_PAGES` | 300 | Only the first N pages are read |
| `FULL_CONTEXT_CHAR_LIMIT` | 120,000 | Up to this much text, the whole PDF is sent |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | 1500 / 200 | Chunking for large PDFs |
| `TOP_K_CHUNKS` | 10 | Chunks sent to Gemini for large PDFs |
| `HISTORY_PAIRS` | 3 | Previous Q&A pairs included for follow-ups |

You can also change the model without editing code: use **Advanced** in the sidebar, or set a `GEMINI_MODEL` secret / environment variable. Model names and availability change over time. The current list is at <https://ai.google.dev/models>.

## Troubleshooting

| Message / symptom | Fix |
|---|---|
| "Gemini rejected the API key" | Re-copy the key, make sure it is active and allowed to use the Gemini API. |
| "rate limit or quota was reached" | Wait a minute, or check usage/limits in Google AI Studio. |
| "The model was not found" | Open **Advanced** in the sidebar and enter a model from <https://ai.google.dev/models>. |
| "No text could be extracted" | The PDF is scanned images. Run OCR on it first, then upload again. |
| "password-protected" | Upload an unlocked copy. |
| Answers miss details in a very large PDF | Keyword search may not pick the right chunks. Rephrase using words that appear in the document. |
| Build fails on Streamlit Cloud | Check that `requirements.txt` and `app.py` are at the repository root. |

## Manual test checklist

1. Upload a normal text PDF, ask a question whose answer you know, and check the cited page.
2. Ask something the PDF does not cover; the app should say the document doesn't contain it.
3. Ask a follow-up ("and what about the second one?") and check it uses the earlier context.
4. Upload a scanned PDF, a password-protected PDF and a non-PDF renamed to `.pdf`; each should give a clear error.
5. Use a wrong API key; you should see the key error, not a crash.
6. Upload a large PDF (100+ pages) and ask about something deep inside it.

## Limitations and ideas for improvement

- **No OCR**: scanned PDFs are rejected. Add OCR (for example Tesseract) or send pages to Gemini as images.
- **Keyword retrieval** for large PDFs cannot match synonyms. Upgrade to semantic search with Gemini embeddings plus a vector index (FAISS, Chroma).
- Tables and multi-column layouts may extract in a jumbled order.
- One document per session; the chat is not saved after the browser tab closes.
- Ideas: streaming answers, multi-PDF chat, downloadable chat transcripts, answer-quality evaluation set, caching embeddings.
